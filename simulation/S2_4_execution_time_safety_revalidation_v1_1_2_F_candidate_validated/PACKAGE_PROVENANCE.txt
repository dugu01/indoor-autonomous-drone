Original F audit result
-----------------------
S2.3/S2.4-E already contained future-route newly-blocked-cell checking, braking/replanning,
planning-time known-free stopping support, perception-degraded hold, scan hold, RTL, landing and
failsafe. The actual request-level gap was post-acceptance execution authority: expiry, remaining
route, viewpoint/hold support and retreat authority were not revalidated during TRACK_OUTBOUND.
The E admission validator also lacked full retreat-route geometry validation.

First coupled MATLAB result -> v1.1.1
------------------------------------
The user's v1.1.0 run preserved E PASS but exposed authority-relative fault-timing and fixture
issues. v1.1.1 changed only F scheduling/fixtures and kept E geometry and the frozen parent intact.

Second coupled MATLAB result -> v1.1.2
------------------------------------
The user's v1.1.1 run again preserved the full E MATLAB gate. F1 then failed before any validation
fault could inject: three exploration authority generations were revoked with
KNOWN_FREE_STOP_INVALID. The same pre-fault invalidation prevented F2-F14 hooks from reaching their
intended execution conditions.

Source audit localized the defect to F's runtime revalidator. It was re-running frozen
validate_known_free_stop_S2_3 on every active execution sample. That helper is used by inherited
S2.3 planning to certify a newly planned terminal stop and includes terminal endpoint footprint
clearance; it is not the inherited live route-change supervisor.

v1.1.2 correction
-----------------
- Frozen validate_known_free_stop_S2_3 remains byte-identical and remains in the planning path.
- Runtime F no longer calls that planning-time terminal gate every cycle.
- Runtime stopping support uses the same conservative first-principles stop distance
  v^2/(2*a_decel) + v*t_delay + margin against the current remaining route on the already-inflated
  execution grid.
- When remaining route length is shorter than d_stop, only the shortfall must be supported by a
  known-free terminal overrun disk around the validated viewpoint.
- A negative backtest rejects a high-speed short-route case when the required overrun region is
  unavailable, so the safety condition is not weakened just to recover E parity.
- The independent Python backtest now includes stopping support; the old model omitted it and was
  insufficient evidence for v1.1.1.
- MATLAB failure diagnostics now expose d_stop, remaining route length, route reserve, overrun
  shortfall, and terminal-overrun result if any case still fails.
