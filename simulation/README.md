# Simulation Directory

Staged MATLAB simulation of the indoor autonomous drone (F450 quadrotor). Each
stage keeps a locked run interface and adds one capability on top of the
previous validated stage.

| Stage | Directory | Capability |
| ----- | --------- | ---------- |
| S1 | `S1_dynamics_pid/` | 6-DoF quadrotor dynamics + cascaded PID |
| S2 | `S2_visual_slam/` | LiDAR SLAM (ICP + ScanContext + pose graph) with quaternion ESKF; F450 flight animation |
| S2.1 | `S2_1_robust_multilane/` | Four-lane estimator with fault detection and lane switching |
| S2.2 | `S2_2_mission_replanning_*` | Autonomous D\*/A\* mission replanning, failsafe and RTL logic |
| S2.3 | `S2_3_online_mapping_*` | Probabilistic online occupancy mapping + safe receding-horizon navigation |
| S2.4 | `S2_4_uncertainty_active_exploration_*` | Uncertainty-aware, target-directed active exploration |
| S3 | `S3_obstacle_avoidance/` | *planned* |
| S4 | `S4_aruco_landing/` | *planned* |

Multiple `*_validated` / `*_development` snapshots are retained per stage for
traceability; the highest `v*_validated` directory is the current baseline for
that stage. Superseded failed iterations are archived in
[`../docs/failed-iterations/`](../docs/failed-iterations).

Generated outputs are written to [`../data/results/`](../data/results). Raw
`.mat` / `.fig` trial data is git-ignored and regenerated by re-running the
stage entry point (see each stage's own README).

## Running a stage

```matlab
cd code; setup_check          % verify toolboxes once
cd ../simulation/S2_visual_slam
results = run_S2_lidar_slam(0, true, true, true);   % seed, stress, plots, animation
```
